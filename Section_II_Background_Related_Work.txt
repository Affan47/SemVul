Section II: Background and Related Work

Software vulnerability detection has moved from manual audit and rule-based static analysis toward data-driven approaches that can scale to large codebases. Early static analyzers relied on hand-crafted patterns over AST or CFG fragments, which delivered high precision for specific weaknesses but struggled with recall and generalization. The rise of machine learning introduced representations that encode syntactic, semantic, and control-flow context as features for classifiers. In vulnerability detection, this shift is driven by two needs: capturing long-range dependencies in code and modeling program semantics that are often invisible in surface-level token patterns. Our work follows this trajectory by using Code Property Graphs (CPGs) and multi-source embeddings to model both structure and content, and it is positioned within the active literature on graph-based and transformer-based vulnerability detection.

A key foundation for this line of work is the Devign dataset, which was introduced to support data-driven vulnerability detection at the function level. Devign includes labeled C functions with vulnerability annotations and has become a common benchmark for graph-based methods. The original Devign approach models functions as graphs derived from program analysis, then uses graph neural networks to classify vulnerability status. This dataset has shaped subsequent research because it offers a consistent experimental setting and because its function-level focus aligns with practical code review tasks. Our pipeline preserves Devign compatibility while extending it with richer semantic signals and stricter dataset hygiene to mitigate leakage and representation mismatch. In our study, Devign serves both as a baseline and as a reference point for the improvements introduced by CPG-driven representations and embedding fusion.

Program representation is central to vulnerability detection. Traditional representations include ASTs, CFGs, data-flow graphs, and call graphs. Each captures a different aspect of program behavior: ASTs provide syntax structure, CFGs capture execution paths, and data-flow graphs highlight variable dependencies. Code Property Graphs unify these views into a single, typed, multi-edge graph by merging syntax, control, and data dependencies. CPGs are a natural fit for graph learning because they expose a rich set of nodes, edges, and attributes that can be mapped to discrete vocabularies or vector embeddings. Tools such as Joern automate the extraction of CPGs from source code and have become the de facto standard in security research. In our pipeline, Joern is used to parse per-function code and export GraphSON graphs, enabling consistent downstream processing across datasets.

Graph-based vulnerability detection builds on message passing over program graphs. Graph neural networks learn representations by iteratively aggregating information from neighbors, allowing them to encode localized and long-range dependencies. Prior work explores multiple architectures including GCNs, GATs, GGNNs, and heterogeneous or hypergraph models that handle typed edges. The Devign model itself uses a gated graph neural network to classify functions, while later work introduces hierarchical pooling, edge type attention, and semantic enhancements. In our architecture, the graph model is configurable with multiple GNN layers, edge-aware operators, and pooling variants such as multi-statistic pooling to capture global structure. These design choices align with the literature that emphasizes the importance of edge types, node types, and hierarchical composition in vulnerability prediction.

A related direction focuses on richer graph semantics. CPGs encode different edge classes such as AST, CFG, CDG, DDG, and CALL, which can be assigned typed embeddings or one-hot encodings. Several studies show that explicitly modeling edge types improves vulnerability detection because control and data dependencies convey the flow of potentially unsafe operations. Graphs built from CPGs also include node properties such as code tokens, identifier names, and operator types. Recent methods incorporate additional signals such as call awareness, interprocedural edges, or domain-specific features. Our pipeline supports these enhancements through configurable vocabularies and a structured schema that aligns node and edge types with the underlying GraphSON exports. This alignment ensures that the model operates on a faithful representation of the program semantics extracted by the analysis frontend.

Parallel to graph learning, transformer-based models have reshaped code understanding. Models such as CodeBERT, GraphCodeBERT, CodeT5+, and UniXcoder are pretrained on large corpora with objectives tailored to code, and have achieved strong results in tasks like function name prediction, code search, and defect detection. These models capture token-level semantics and long-range dependencies that are difficult to express in graph-only approaches. However, they typically operate on linearized code sequences and can underutilize explicit program structure. In vulnerability detection, transformer embeddings are often used as inputs to classifiers or as features attached to graph nodes. Our architecture acknowledges this trade-off and integrates transformer-derived embeddings with graph structural signals, aiming to combine semantic richness with program dependence structure.

Hybrid approaches that fuse graphs and language models are increasingly common. Some methods use transformers to encode code tokens and then map them onto graph nodes, while others perform late fusion by combining graph-level embeddings with sequence-level representations. The choice of fusion strategy affects training stability and interpretability. In our pipeline, embeddings are extracted for both node content and edge content, then merged with structural features using configurable fusion modes such as early concatenation. This design is motivated by prior work showing that textual content alone can miss control or data dependencies, while pure structural models can miss semantic cues. By integrating both, we target a representation that is robust to syntactic variation and retains contextual semantics critical for identifying vulnerabilities.

Dataset preparation is another key component in related work. Vulnerability datasets often suffer from duplicates, near-duplicates, or split contamination that inflates validation performance. Hash-based deduplication is a common remedy, but the hashing strategy must reflect the actual code content to avoid mismatches. Our preprocessing stages compute hashes over normalized function sources and enforce split separation to reduce leakage. We also normalize whitespace and remove comments where appropriate to reduce noise, while preserving the semantics of string and character literals. These choices are grounded in prior research that emphasizes dataset integrity and realistic evaluation conditions. By applying consistent preprocessing across Devign, Reveal, and Draper datasets, we can compare models under a controlled experimental setup.

The vocabulary and embedding pipeline also builds on related work in representation learning. Traditional code embeddings use word2vec or fastText to capture token co-occurrence, while newer approaches use subword tokenization and transformer encoders. For graph-based models, vocabularies are built for node types, edge types, and content strings, and embeddings are cached to scale to large datasets. Our pipeline uses vocabulary builders that extract both node and edge content, and a multi-extractor that can generate embeddings from various pretrained models or custom word2vec spaces. This flexibility allows us to evaluate different embedding sources in a consistent graph-based framework and to quantify how semantic enrichment affects downstream classification.

Finally, our methodology aligns with the broader trend toward scalable, reproducible pipelines. Many prior works describe novel architectures but provide limited detail on data extraction, graph construction, or embedding management. We emphasize an end-to-end, reproducible workflow: per-function splitting, CPG generation, GraphSON parsing, vocabulary construction, embedding extraction, cache management, and model training. This workflow reduces hidden variability and makes it easier to attribute performance changes to specific components. It also enables straightforward extension to new datasets by updating dataset-specific parsers and configuration schemas, which is critical for evaluating generalization across codebases and domains.

In summary, the related work spans three key axes: program graph representations, transformer-based code understanding, and hybrid fusion methods. CPGs provide a principled way to capture program semantics, and graph neural networks are well suited for leveraging these structures. Transformer models bring rich token-level semantics that can complement graph signals. Our work sits at the intersection of these areas by integrating node and edge content embeddings with CPG structure, grounded in a robust data pipeline. This positioning is consistent with recent efforts to bridge the gap between structured program analysis and modern representation learning, and it motivates the methodological choices described in the next section.

Another relevant thread in the literature compares static and dynamic analysis for vulnerability detection. Dynamic approaches can capture runtime behavior but require test inputs and impose significant overhead, which limits scalability across large repositories. Static approaches are more scalable but must approximate program behavior and can miss path-sensitive issues. CPG-based analysis provides a middle ground by encoding control and data dependencies in a static graph, allowing learning methods to reason about potential flows without executing code. Studies on program slicing and taint analysis show that data-flow relationships are critical for detecting memory safety bugs and misuse of APIs. By embedding these relationships as explicit edges, graph models can learn patterns such as unsafe pointer arithmetic, missing checks, or propagation of untrusted input. This reinforces the choice of CPGs and edge-type-aware models for our task.

There is also a growing body of work on the practicalities of graph extraction and schema alignment. Different graph export formats expose slightly different fields, and mismatches between the graph schema and model assumptions can silently degrade performance. GraphSON, for example, contains typed nodes and edges with property dictionaries, but the mapping from properties to model features requires careful normalization. Our pipeline explicitly builds vocabularies for node types, edge types, and content strings, and maintains configuration files that mirror the extracted schema. This design follows best practices in related work, where schema discovery and validation are necessary to avoid missing edge categories or ignoring useful attributes. By enforcing alignment between the extraction schema and the training configuration, we reduce the risk of representation drift when moving across datasets or Joern versions.

Another related theme is the evaluation of imbalanced vulnerability datasets. Real-world code has far more non-vulnerable functions than vulnerable ones, so metrics like accuracy can be misleading. Prior work emphasizes the use of AUC, precision, recall, and F1 to capture detection quality. Many approaches also introduce class-balanced loss functions, focal loss variants, or label smoothing to improve training stability. Our training setup follows this guidance by reporting F1 and AUC, supporting combined loss types, and allowing early stopping based on the most informative metric. This perspective is important for positioning results in a way that aligns with current evaluation practices in vulnerability detection and software security.

Finally, cross-dataset generalization is a recurring concern in related work. Devign and Reveal are curated datasets with different labeling protocols and function extraction processes, while Draper includes broader CWE annotations and distinct code sources. Models that perform well on one dataset often degrade on another, highlighting the influence of dataset composition and preprocessing. Our pipeline is designed to minimize these confounds by standardizing preprocessing, per-function splitting, and graph extraction across datasets. This standardization enables more meaningful cross-dataset comparisons and supports claims about generalization and robustness. It also allows future extensions, such as adding new datasets or incorporating additional program analysis overlays, without reengineering the core pipeline.

Recent work also explores self-supervised and contrastive objectives for code representations. Contrastive learning can align augmented views of the same function, or align graph and token representations, improving downstream classification when labeled data is limited. Approaches such as graph contrastive learning and masked token prediction aim to capture invariances that reflect program semantics rather than surface syntax. These techniques are particularly relevant in vulnerability detection, where labels are noisy and vulnerability patterns can be subtle. In our study, we include contrastive pretraining and fine-tuning setups for graph models, reflecting the broader trend toward leveraging self-supervision to improve generalization. This choice is supported by related work showing that pretraining can stabilize optimization, reduce overfitting, and yield better feature reuse across datasets. As a result, the methodology in our paper is not only grounded in established supervised baselines but also aligned with modern representation learning techniques that are increasingly expected in security-oriented machine learning research.

Overall, the literature points to a convergence: effective vulnerability detection requires both program structure and semantic content, robust preprocessing, and transparent evaluation. Graph-based methods excel at capturing dependencies, transformers excel at modeling code semantics, and hybrid systems often outperform either alone. Our contribution is situated precisely at this intersection, with a pipeline that operationalizes these ideas at scale. The next section details how we instantiate this design in a unified architecture that preserves the strengths of each representation while addressing dataset-specific challenges encountered in Devign, Reveal, and Draper.
